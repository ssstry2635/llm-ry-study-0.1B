# 我的学习与训练过程

> 基于仓库代码、讲义、训练日志和原始复盘整理。讲义说明学习路径；有运行产物支持的部分才记录为完成的实验。

## 起点：补齐 Python 和神经网络基础

我的目标是理解语言模型怎样从文本中学习，并在自己的电脑上完成预训练。仓库中的 Python 材料从变量、循环、函数和容器开始，延伸到文件 / JSON、模块、异常、类、生成器、类型注解和 NumPy。

基础项目分别用纯 Python 与 NumPy 实现小型神经网络，帮助理解矩阵运算、前向传播和梯度。再读 PyTorch 训练循环时，便能把 `loss.backward()` 和 `optimizer.step()` 与背后的计算联系起来。

入口：[Python 学习路线](../从0开始学python/README.md)、[手写神经网络](../从0开始学python/project/README.md)。

## 确定本机能完成的目标

项目选择约 0.1B 参数的 decoder-only GPT：12 层、768 维、12 个注意力头、1,024 上下文。最终独立参数量为 110,119,680，由测试逐位校验。

硬件是 RTX 4060 Laptop 8GB。代码包含 bf16、梯度累积、AdamW、warmup + cosine 与断点续训。原始复盘记录了先估算算力和显存，再决定规模的思路。

## 数据：先检查，再决定清洗规则

语料来自中文维基百科 `20231101.zh` 和 TinyStories V2 GPT-4 英文故事。中文需要规整空白、繁转简、过滤过短或中文占比过低的文档；两种语言都做精确去重，再按内容哈希划分训练 / 验证集。

统计保留中文 **990,107** 篇、英文 **2,717,409** 篇。清洗统计中的 token 数是字符比例估算；真实 token 数应以 token 化日志为准。这一步让我把数据检查与工程决策联系起来。

## 分词器：从正确性到速度

实现 byte-level BPE，词表规模 32,768。字节表示覆盖任意 UTF-8 文本；预分词与高频字节对合并缩短序列。

原始复盘记录了过滤低频词块、缓存合并优先级表、用堆和链表维护局部合并等优化。优化中曾出现哨兵导致的提前终止，通过新旧实现对拍定位。仓库保留最终实现与编解码边界测试，原始对拍脚本未保存。

日志记录词表训练约 **9.2 分钟**；中文验证采样压缩率 **0.645 token/字符**。词表使用训练文件前部约 1.5 亿字符，不能称为中英文均衡采样。

## 模型：逐个组件实现，再检查整体

模型包括 RMSNorm、RoPE、因果自注意力、SwiGLU、残差与输入 / 输出权重共享。注意力提供手写版和 PyTorch SDPA 版。

测试覆盖参数量、初始 loss、输出形状、因果性、RoPE 性质、attention 对拍和单 batch 过拟合。正式训练前先用合成数据检查链路，再用真实规模模型试测显存。合成数据极低的 loss 只说明训练链路能学习规律，不是语言建模成绩。

## 本机训练：小 batch、续训与观察

micro-batch 4、序列长度 1,024、累积 16 次，每次更新名义处理 65,536 tokens。日志记录完成 15,000 步，期间有中断续训和降温休息。稳定阶段吞吐约 20.4k token/s，末段显存峰值约 6.0 GiB。

最佳 checkpoint 位于第 14,750 步，随机采样验证 loss 为 1.7797412872314453。公开整理时发现：历史脚本累积的是梯度之和，没有除以累积次数；它与规范的大 batch 平均梯度不等价。这次实验保留历史实现，改进需要另做受控比较。

## 生成和复盘：用实际输出认识边界

命令行支持 temperature、top-k、top-p，本地网页提供续写交互。模型没有 SFT，输入应是需要续写的开头。中英文质量可能不同，也可能重复或编造；loss 下降并不代表具备可靠问答能力。
